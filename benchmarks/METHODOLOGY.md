# Benchmark Methodology

> **Status:** methodology defined, results pending a local run.
> This document describes *how* Cerbère's detection layers are measured.
> Actual numbers live in [`BENCHMARK.md`](../BENCHMARK.md) and are generated by
> `benchmarks/run_and_publish.py` — never hand-written.

## 1. What we measure

Cerbère ships three detection layers. Each is measured **independently** and
**cumulatively**, so the marginal value of every layer is visible:

| Layer | Component | What it catches |
|-------|-----------|-----------------|
| **L1 — Rules** | `agentguard/patterns.py` | Known signatures: direct injection, jailbreak phrasing, system-prompt extraction, exfiltration, dangerous commands, obfuscation (base64/hex/leetspeak), multilingual variants (EN/FR/ES/DE/IT) |
| **L2 — ML classifier** | `agentguard/detector.py` | Paraphrased / unseen attacks that evade regex |
| **L3 — LLM judge** | `agentguard/judges.py` | Semantic intent, indirect injection, ambiguous cases |

**Reported configurations:**

- `L1` — rules only (baseline)
- `L1+L2` — rules + ML
- `L1+L2+L3` — full stack (default)

> ⚠️ The previous benchmark ran with `AGENTGUARD_USE_ML=false` and
> `AGENTGUARD_USE_LLM_JUDGE=false`, i.e. it measured **L1 only** while the
> README advertised three layers. This methodology fixes that: the default is
> the **full stack**, and L1-only is reported explicitly as a baseline.

## 2. Metrics

For each configuration we report:

- **Recall (TPR)** — attacks correctly blocked / total attacks. *Primary metric: a missed attack is a security failure.*
- **Precision** — true attacks / everything flagged. *Controls alert fatigue.*
- **False Positive Rate (FPR)** — benign prompts wrongly blocked / total benign. *Primary metric for usability.*
- **F1** — harmonic mean of precision and recall.
- **Latency** — p50 / p95 / mean per prompt, in ms.
- **Confusion matrix** — TP / FN / TN / FP.

**Targets (engineering goals, not guarantees):** Recall ≥ 99%, FPR ≤ 1%, p95 latency ≤ 50 ms for L1.

## 3. Datasets

### 3.1 Internal adversarial corpus

`benchmarks/adversarial_corpus.json` — 168 prompts across 8 categories
(direct_injection, jailbreak, system_extraction, exfiltration,
dangerous_commands, encoded_obfuscated, indirect_injection, benign),
multilingual (en/fr/es/de/it).

**Limitation:** authored by the same team that wrote the patterns. This is a
*development* corpus and is reported as such. It is **not** sufficient on its own.

### 3.2 External holdout set (required for credibility)

`benchmarks/external_holdout.json` — prompts sourced from **public, independent**
datasets, with attribution. This set is **never** used to tune patterns.

Recommended public sources:

- **OWASP LLM Top 10** — prompt injection examples (LLM01)
- **deepset/prompt-injections** (HuggingFace)
- **JailbreakBench** — jailbreak prompts
- **AdvBench** (Zou et al.) — harmful-behaviour prompts
- **HarmBench** — standardised red-teaming behaviours
- **BIPIA** — indirect prompt injection benchmarks

Each entry must carry: `text`, `label` (`attack`/`benign`), `category`, `source`.

### 3.3 Benign control set

To make FPR statistically meaningful we need **≥ 200 benign prompts**
(the current 20 give a ±10% margin of error). Benign prompts must cover:
normal dev questions, code review, data analysis, customer support, creative
writing, and multilingual everyday requests — **including hard negatives**
(prompts that *mention* security topics without being attacks, e.g.
"how do prompt injections work?").

## 4. Protocol

1. Freeze the corpus (hash it) before running — no edits after seeing results.
2. Run each configuration (`L1`, `L1+L2`, `L1+L2+L3`) on the **same** frozen corpus.
3. Report internal corpus and external holdout **separately** — never merge them.
4. Publish the exact command and the corpus hash alongside the numbers.
5. Report failures honestly, including worst cases.

## 5. Reproducing

```bash
# Full stack (default)
python benchmarks/benchmark.py --layers l1,l2,l3 -r BENCHMARK.md

# Baseline: rules only
python benchmarks/benchmark.py --layers l1 -r reports/l1_only.md

# External holdout
python benchmarks/benchmark.py --corpus benchmarks/external_holdout.json --layers l1,l2,l3
```

## 6. Known limitations (stated up front)

- The internal corpus is small and self-authored; treat its numbers as an upper bound.
- ML and LLM-judge layers add latency and cost; L1-only numbers are the fast path.
- No third-party audit has been performed yet.
- Results are environment-dependent (model version, hardware). Always publish the environment.
